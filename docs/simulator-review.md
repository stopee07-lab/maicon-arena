## 재검토에서 확인한 차이

민현님 UI를 실제 브라우저로 확인했습니다. 조건 선택, 크게 보이는 실행 버튼, 중앙 이동 경로와 시간 막대, 오른쪽 진단이 연결돼 다음 행동을 찾기 쉽습니다. 우리 기존 화면은 코드·학습·배포·센서·제어가 처음부터 함께 보여 초보자가 경기장에 도달하기 어려웠습니다. 새 기본 경기 화면은 3D·카메라를 위로 옮기고, 세부 조작은 별도 보기로 이동했습니다.

민현님 모델은 대상 ID와 관측 위치를 제공하는 축약 시뮬레이션입니다. 실제 사진에서 물체를 찾는 YOLO·ROS·강체물리 검증을 대체하지 않습니다. 최대 점수와 일부 임무의 대리 지표도 달라 총점으로 우리 환경과 우열을 판단하지 않았습니다. 관측 신선도·중복 방지 등 이미 우리 코드에 있는 기능은 중복 추가하지 않았습니다.

수현님 환경의 간단한 임무 흐름과 배치 편집은 유용한 후보입니다. 다만 기본 정책에는 관리자 정보에 의존하는 경로가 있어 그대로 참가자 코드에 통합하지 않았습니다. 이번 API 도구는 완료된 공식 형태의 `/api/report/*` 요청·응답만 읽고, 보고를 대신 제출하지 않습니다. 최근 200개만 보관하고 인증키·임무코드·영상·헤더를 숨깁니다.

## 비교의 의미를 지키는 장치

- 경기 조건 번호, 규칙·센서·상대 설정, 물리/연습 모드, 배속, 다른 로봇 역할·참가 여부, 모든 장애 설정을 비교합니다.
- 경기 중 장애를 켰다가 끈 경우도 조건 변경 이력을 확인합니다. 조건이 다르거나 정보가 없으면 최종 점수 차이 계산을 보류합니다.
- 미완주·연습 기록은 확정 성적과 분리합니다. 여러 실행을 포함할 수 있는 일반 내보내기에 현재 선택한 모델/코드 해시를 임의로 붙이지 않습니다.
- 예제는 2026-11-14 실제 보존 경기의 위치·이벤트를 축약했습니다. 원본과 실험 명세 해시를 보존하고 원본 위치와 일치하는지 확인했습니다.
- 반복 실험의 최저점·중앙값·성공률과 실패 원인을 함께 봐야 합니다. 이번 변경은 전략·주행·인식·채점 변경이 아니며 점수 향상 실험도 아닙니다.

## 이번 범위 밖의 후보

배치 편집, 대규모 반복 실험의 통계 화면, 인식 투표 방식은 후속 후보입니다. 기존 평가 실행기·실험 기록에 연결하고, 같은 입력과 다양한 실제 조건에서 효과를 확인한 뒤 적용해야 합니다. 두 시뮬레이터의 점수 공식을 섞거나 관리자 정답을 참가자에게 전달하는 방식은 채택하지 않습니다.
