# 경기·녹화 / 관제 상세 통합 (2026-11-17)

## 확인한 원인

8897 서버에서 경기 상태는 running/paused였지만 물리 엔진은 정지하고 참가 프로그램도 exit 0으로 종료되어 있었다. 기존 관제 상세의 reset/start/resume은 경기 상태만 바꿨고, 코드·모델·물리 엔진의 준비를 보장하지 않았다. running 상태가 남으면서 코드 적용도 경기 중 수정 잠금(409)에 걸렸다. 사용자 수정 참가 코드는 앞선 실행에서 실제 이동/보고 로그가 있었다.

## 적용한 변경

- 5번 경기·녹화에서 시작·일시정지·재개·종료·초기화, 점수, 시간, 이벤트, 로봇 상세, 기록 내보내기를 함께 제공한다.
- 기존 관리자 관제 상세 주소는 선택 환경을 유지한 채 5번 화면으로 이동한다. 관전자 주소는 읽기 전용으로 유지한다.
- 실행기가 없는 상태에서는 준비된 코드 버전·모델·정책을 그대로 사용해 전체 실행 준비를 수행한다. 진행 중이던 경기를 다시 시작할 때는 새 경기 시작이라고 표시한다.
- 전체 정지는 진행 중 경기를 종료하여 수정 잠금을 해제한다. 종료 전 기록을 보존하고 종료 시점의 잠정 점수를 계산한다.
- 선택 경기의 초기화는 해당 실행기를 먼저 정지한다. 준비되지 않은 엔진·참가 코드의 start/resume은 거절한다. 준비 버튼의 잘못된 재요청과 리허설 대기 중 연결 종료도 검사한다.
- 사용자 수정 `workspace/participant_supervisor.py`는 변경하지 않았다.

## 사용 순서

1. 코드 수정 화면에서 원하는 버전을 적용하거나 실행 설정에서 사용할 코드·모델을 준비한다.
2. 5번 경기·녹화에서 실행 환경을 경기로 선택하고 **코드·경기장 실행**을 누른다.
3. 이후 제어와 점수·이벤트·녹화 확인은 같은 화면에서 한다. 실행기가 정지했다면 **코드 적용 후 새 경기 시작**으로 다시 시작한다.
