ABOUT THE SIMULATOR

구현 범위와 자료 근거

공식 교육자료의 경기장과 UGV를 바탕으로 만든 로컬 연습용 시뮬레이터입니다. 아래의 차이를 확인하고 실제 로봇 검증과 함께 사용하세요.

01

교육자료에서 확인

경기장 약 6.12 × 5.00 m, 벽 높이 0.40 m, 20 cm 바닥 격자, 양 진영 각 3개 섹터·거점. UGV 250 × 230 × 320 mm, 6륜 구조와 팬틸트·카메라·라이다.

02

이 환경의 근사

장애물 위치·표적 배치·주행·레이저 판정은 단순화한 시뮬레이션입니다. Gazebo 물리 엔진이나 실측 디지털 트윈이 아닙니다. 합성 카메라는 실제 영상 도메인과 다릅니다.

03

전략 실험과 학습

기본 상대는 센서 기반 정책이며 학습된 AI가 아닙니다. 특권 시연 정책은 설정에서 별도로 선택합니다. 내 Python / ROS 2 제어기는 별도 센서 API로 연결합니다. 실제 모델 훈련은 데이터 생성과 학습 명령 실행이 필요합니다.

04

공식 규칙과 구현

공식 경기 API와 시뮬레이터용 로봇 API는 구분됩니다. 점수·판정의 미확정 사항은 서버가 아래에 표시합니다. 실제 대회 공지와 로봇에서 반드시 다시 검증하세요.

현재 구현의 가정

  • 서버 연결 후 표시됩니다.

근거: 1차 교육자료 p.21(UGV), p.23–25(경기장·이벤트 장치), p.26(대시보드) · 공식 game-server-api.html. 세부 대응표는 프로젝트의 docs/rules-audit.md를 참고하세요.
ROBOT INTERFACE

내 코드로 움직이는 UGV

워크벤치에서 슬롯을 고른 뒤 외부 제어를 활성화하세요. 선택한 로봇은 스크립트 대신 Python / ROS 2의 명령을 기다립니다.

  1. 선택한 로봇의 접속 정보 확인mission_code는 해당 로봇의 센서·명령·공식 보고 API를 식별합니다.
  2. 별도 프로세스에서 제어기 실행프로젝트의 README 및 docs/robot-training.md에 있는 예제로 연결하세요. 브라우저는 업로드한 Python을 실행하지 않습니다.
  3. 경기를 준비하고 시작센서와 경기 지시를 읽어 속도·팬틸트·레이저 명령을 전송합니다. 속도 명령은 0.5초 watchdog으로 멈춥니다.

Mac 예제 제어기

simulator 폴더에서 실행 · 기본 센서 기반 주행 데모입니다.

python3 examples/mac_team.py \
  --mission-code '내 로봇의 접속 코드' \
  --mode match --duration 360 \
  --camera-output output/own-camera.jpg

외부 제어기는 1× 배속을 사용하세요. 5× / 20×에서는 서버 시간 기준 watchdog이 실제 명령 주기보다 빠르게 만료됩니다.

별도 합성 데이터 학습

운영자 키로 데이터셋을 내보낸 후, 필요한 학습 패키지를 설치하고 실행합니다. 아래 명령을 표시한 것만으로 학습이 실행되지는 않습니다.

SIM_ADMIN_KEY='운영자 키' \
python3 training/export_dataset.py \
  --output training/datasets/synthetic-v1 \
  --count 120 --seed 42

python3 training/train_yolo.py \
  --data training/datasets/synthetic-v1/data.yaml \
  --model yolo26n.yaml --epochs 30 --device cpu
센서 · 로봇 자신만 관측GET /sim/robot/stateGET /sim/robot/camera로봇 제어POST /sim/robot/cmd_velPOST /sim/robot/gimbalPOST /sim/robot/fire공식 경기 연동/api/report/me · /order · /target

이 시뮬레이터의 합성 영상과 라이다는 실물 센서의 특성을 전부 재현하지 않습니다. ROS 2 연결 규격은 별도 어댑터이며 공식 커스텀 메시지와의 바이너리 호환을 보장하지 않습니다.
